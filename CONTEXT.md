# Caspian Breeze — контекст проекта

## Суть
Веб-платформа теплового комфорта г. Актау (Мангистауская обл.):
1) карта зон перегрева (Urban Heat Islands) по микрорайонам — индекс дефицита тени;
2) карта точек охлаждения: ❄️ остановки с кондиционером и ТРЦ, 💧 питьевая вода, 🌳 тенистые зоны, 🌊 набережная/бриз;
3) CoolPath — из вариантов пешего маршрута выбирается тот, где меньше солнца и больше точек охлаждения рядом;
4) жители отмечают проблемы («нет тени», «нужен фонтанчик», «сломан кондиционер на остановке»);
5) панель диспетчера акимата: KPI, тепловая карта обращений, рейтинг микрорайонов, смена статусов, CSV.

Сквозной демо-сценарий (для питча): жара +41 °C → житель строит CoolPath «27 мкр → Набережная» →
на пути открытый участок → «Сообщить: здесь нет тени» → акимат видит рост индекса дефицита в мкр →
меняет статус «Запланирован навес» → житель видит новый статус по номеру заявки.

## Обязательные требования ТЗ
- Продукт задеплоен и доступен по ссылке; данные сохраняются.
- Свой backend + реальная БД. НИКАКОГО localStorage для данных.
- Реальная привязка к Актау/Мангистау (микрорайоны, реальные объекты, погода Актау).
- Визуализация: карта, тепловая карта, дашборд.
- Полный сценарий «проблема → реакция».
- Понятно, кто пользуется: жители/туристы + акимат/ЖКХ/отдел благоустройства.

## Стек
Основной (переносим сюда функции, этапы 1–8):
- Backend: Python 3.11, FastAPI, SQLAlchemy 2, GeoAlchemy2, Alembic, PostgreSQL 16 + PostGIS (backend/).
- Frontend: React + Vite + TypeScript, Leaflet (react-leaflet), leaflet.heat, Recharts (frontend/).
- Запуск: docker compose (db + backend + frontend). Конфиг через .env (.env.example).
- Внешние API без ключа: Open-Meteo (погода Актау), OSRM routing.openstreetmap.de (foot).
- Деплой: Railway/Render (backend + Postgres), Vercel (frontend).

Запасной (офлайн-демо на питче): app.py — Streamlit + SQLite + Folium. Основной стек готов (этапы 1–9).
Логику (индекс дефицита тени, CoolPath, seed-данные Актау) переносить из app.py, не придумывать заново.
